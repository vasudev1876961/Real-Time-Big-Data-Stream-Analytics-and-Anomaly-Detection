Problem Formulation

Why Traditional Batch Processing Fails

High-velocity industrial systems cannot wait for hourly or daily ETL runs.

❌ The Batch Dilemma

  • Millions of records accumulate in cold storage before analysis.
  • Detection Latency = Batch Schedule Interval + Query Time.
  • A sudden bearing failure or cavitation spike goes undetected for hours.
  • Results in destructive physical equipment loss and emergency downtime.

✅ The Streaming Solution

  • Process events continuously as they cross the network boundary.
  • Stateful tumbling and sliding window aggregations (10s–60s).
  • Sub-second to low-second end-to-end alert dispatch.
  • Decoupled message buffering absorbs rate surges up to 1,000+ Hz.
Mathematical Objective: Minimize E2E Latency L = T_display - T_event while maximizing F1-Score on Point, Collective, and Multivariate Outliers.
System Design

End-to-End Pipeline Architecture

Decoupled, event-driven streaming topology executing locally on a single machine.

1. Ingestion Layer

Producer & Kafka:

  • Synthetic generator & dataset replayer.
  • Partitions messages by sensor_id for strict temporal order.
  • Apache Kafka 4.4.0 in KRaft mode (zero ZooKeeper).

2. Processing Layer

Spark Structured Streaming:

  • Ingests from Kafka topic sensor-readings.
  • JSON schema enforcement & watermarking.
  • Calculates windowed aggregates per sensor.
  • Executes Unified Anomaly Detection Engine.

3. Presentation Layer

Persistence & UI:

  • SQLite with Write-Ahead Logging (WAL).
  • Non-blocking concurrent reads and writes.
  • Streamlit interactive glassmorphic dashboard.
  • Plotly multi-sensor time-series visualization.
Pipeline: Sensor Telemetry Generator → Kafka Broker (:9092) → Spark Streaming Engine → SQLite (WAL) → Streamlit (:8501)
Analytical Core

Multi-Method Anomaly Detection Engine

Fair, side-by-side comparison of three distinct mathematical paradigms.

METHOD A

Threshold Detection

Static Operating Envelope:

  • Hard limits: Temp > 75°C, Vib > 0.65g, Press ∉ [85, 115] kPa.
  • Extremely fast (O(1)), zero state.
  • Catches catastrophic point spikes.
  • Misses dynamic drifts and subtle combinations.
METHOD B

Rolling Z-Score

Statistical History (N=30):

  • Evaluates Z = (x - μ) / σ per sensor.
  • Adapts to baseline operational shifts.
  • Protected by physical noise floors (guards against σ = 0).
  • Vulnerable to the "masking effect" during prolonged collective drifts.
METHOD C

Isolation Forest

Unsupervised ML Ensemble:

  • 100 random decision trees partitioning feature space [T, V, P].
  • Pre-trained offline on normal patterns.
  • Flags multivariate outliers where single metrics are individually normal.
  • Delivered 100% precision in tests.
